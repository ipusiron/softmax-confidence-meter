# Softmax Confidence Meter UI仕様書

## 1. 共通方針

- ダークテーマを保ち、本文とのコントラストを確保する
- タイトル、サブタイトル、注意文、タブを中央に配置する
- 320px幅では1列、600px以上で一部を2列、900px以上で入力と結果を2列にする
- 操作要素の高さは44px以上とし、本文入力の文字サイズは16px以上にする
- 長い候補名と英語文でも横スクロールを発生させない
- `prefers-reduced-motion`を尊重する

## 2. ヘッダーと言語切り替え

タイトルと説明は常に中央揃えとする。言語切り替えボタンは狭い画面ではタイトルの上、600px以上ではヘッダー右上に置き、タブと接触させない。

## 3. タブ

次の4タブをARIA tab patternで実装する。

1. softmaxの基本
2. 分布集中度メーター
3. 2条件比較ラボ
4. 関連ツール・発展

クリック、`←`、`→`、`Home`、`End`で移動できる。選択タブだけをTabキーの停止位置にする。

## 4. softmaxの基本

4件の解説を開閉ボタンとして表示し、先頭だけを初期展開する。

1. softmaxとは
2. 温度Tの役割
3. 集中度の読み方
4. 高い最大確率の注意点

開閉ボタンは`aria-expanded`と`aria-controls`を持つ。固定の`max-height`は使わず、翻訳後の文章を切らない。

## 5. 分布集中度メーター

### 入力領域

- 明示的なラベルと入力仕様の説明
- 最大20,000文字の複数行入力
- 4種類の日英サンプル
- 0.10〜5.00の温度スライダーと現在値
- 計算、消去、キーボードショートカット
- 行番号付きエラーを`role="alert"`で通知

### 結果領域

- 初期状態の説明
- 分布集中度と、信頼度ではない旨の注記
- 7種類の指標
- 上位5件の候補名、スコア、割合、`progress`要素
- 省略件数と残り確率の合計
- ネイティブ`details`による全候補表示
- 結果領域を`aria-live="polite"`とする

入力が変更されたら古い結果を非表示にする。計算済みの有効な入力で温度を変えた場合だけ再計算する。

## 6. 2条件比較ラボ

- 冒頭に、分布差から正しさ・優劣・安全性を判定しない旨を表示する
- 4プリセットを`aria-pressed`付きボタンで表示する
- 条件Aと条件Bへ、候補入力と0.1〜10.0の温度数値入力を用意する
- 320pxでは1列、900px以上では条件A・Bと結果A・Bをそれぞれ2列にする
- 入力変更時はプリセット選択状態と古い比較結果を解除する
- 比較エラーを条件名と行番号付きで`role="alert"`へ表示する
- 比較結果を`aria-live="polite"`とする
- 候補集合、順位、実効スコア幅、集中度差、首位割合差、同一候補の最大変化量を表示する
- 候補集合が違う場合は、順位と同一候補の変化量を直接比較不可とする
- 両条件の分布を同じ構成で表示し、各候補を安全なDOM APIで描画する

## 7. 関連ツール・発展

確率校正、スコア変換への感度、不確実性、プライバシーをカードで説明する。softmax出力だけで正しさを判断できないことを明示する。

## 8. 日英切り替え

静的文言だけでなく、表示中のエラー、結果、グラフ、サンプルも切り替える。サンプルを読み込んだ状態では候補名も翻訳する。ユーザーが編集した入力は書き換えない。

## 9. 安全な描画

候補名はDOM APIと`textContent`で描画する。確率バーには`progress`を使い、入力値からHTMLやインラインCSSを生成しない。
